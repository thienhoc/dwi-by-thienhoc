# Governance

## Maintainer

The project is stewarded by thienhoc. Product direction, public visibility, licensing, releases, brand use, and final acceptance remain maintainer decisions.

Contact: [hoc@wi.works](mailto:hoc@wi.works)

## Decision principles

1. Human safety and explicit authority outrank speed.
2. Live files and reproducible evidence outrank summaries and confident prose.
3. A small useful module outranks a large framework without demonstrated need.
4. Compatibility and performance claims remain scoped.
5. English and Vietnamese meaning should move together.
6. Public release requires license, privacy, rights, and evidence gates.

## Change levels

- Editorial: wording or links without behavioral meaning change
- Behavioral: a skill instruction changes agent conduct
- Structural: module boundaries, install paths, or repository contract change
- Release: visibility, license, tag, distribution, or public claim changes

Behavioral and structural changes require a bounded rationale and review evidence. Release changes require explicit maintainer approval.

## Conflicts

When contributors disagree, identify the user outcome, safety boundary, evidence, reversibility, and smallest useful experiment. The maintainer records the final decision in the relevant issue, pull request, or release note.
