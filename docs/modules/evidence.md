# Dwi • Evidence

**Proof status and provenance before "done".**

[Open the installable `SKILL.md`](../../modules/dwi-evidence/SKILL.md) · [Vietnamese guide](../vi/modules/evidence.md)

## Choose Evidence when

- completion language is stronger than the available check;
- a benchmark or comparison needs a denominator and scope;
- static, runtime, and human evidence are being mixed;
- a handoff must preserve failures and unknowns.

## What changes

Evidence labels material claims `VERIFIED`, `OBSERVED`, `ESTIMATED`, `TARGET`, or `UNKNOWN`. It records source, environment, time, method, result, exclusions, and remaining uncertainty at the smallest useful level.

## What does not change

Evidence does not fabricate missing measurements, approvals, or lived experience. It does not turn one benchmark into a universal claim or a passing static check into runtime proof.

## Ten-minute trial

1. Install Evidence using [the inspect-first guide](../installation.md).
2. Give it a recent agent completion report.
3. Ask it to label each material claim and name the missing check.
4. Check whether failures and exclusions remain visible.
5. Remove the module if labels add ceremony without changing a decision.

## A good result

A reader can see what the result supports, in which scope, and what still needs a check or human decision.

Read [the safety model](../safety.md). Follow the [file-level removal steps](../installation.md#remove-a-module) for the exact project or user scope where Evidence was installed, then start a fresh session.
