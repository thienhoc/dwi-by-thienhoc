# Dwi • Lean

**The smallest sufficient path, then stop.**

[Open the installable `SKILL.md`](../../modules/dwi-lean/SKILL.md) · [Vietnamese guide](../vi/modules/lean.md)

## Choose Lean when

- a small request is turning into speculative architecture;
- exploration continues after the relevant files are known;
- testing is broader than the claim being made;
- optional polish is hiding the actual finish line.

## What changes

Lean names the outcome, scope, finish line, and evidence before expanding work. It chooses direct action, a bounded plan, or a risk-controlled path according to the task rather than habit.

## What does not change

Lean does not skip safety, migration, release, or acceptance gates. It does not make "fast" more important than correct enough for the stated risk.

## Ten-minute trial

1. Install Lean at project scope with [the inspect-first guide](../installation.md).
2. Give it one small reversible change.
3. Ask for the smallest sufficient path and explicit stop condition.
4. Compare the plan and checks with your normal workflow.
5. Remove the module if it removes evidence instead of waste.

## A good result

The requested outcome is met with proportionate evidence, and optional work remains visibly optional.

## Safety and removal

Read [the safety model](../safety.md). Follow the [file-level removal steps](../installation.md#remove-a-module) for the exact project or user scope where Lean was installed, then start a fresh session.
