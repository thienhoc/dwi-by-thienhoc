# Dwi v0.2.2

Release type: installation-contract patch

Release date: 2026-07-26

## Summary

Dwi v0.2.2 corrects how modules are installed for Codex and Claude Code so the installed artifact preserves the person's decision about when a module may be activated.

The earlier one-file examples were sufficient for skill discovery but incomplete for explicit-only invocation. They also used a relative destination after entering the Dwi source checkout, which could place a module in the source repository instead of the intended project.

## Fixed

- Codex installations now include both canonical `SKILL.md` and `agents/openai.yaml` with `allow_implicit_invocation: false`.
- Claude Code installations are rendered from canonical `SKILL.md` with exactly one `disable-model-invocation: true` field.
- The installer refuses to overwrite an existing module directory.
- The installer resolves the prospective destination physically and rejects direct or symlinked paths inside the Dwi source checkout.
- Claude repair backups are stored outside `.claude/skills/`, preventing the affected copy from remaining discoverable during verification.
- English and Vietnamese documentation now separate `DWI_ROOT` from `PROJECT_ROOT` and include exact repair and removal paths.

## Upgrade guidance

Use the complete installer from the immutable `v0.2.2` tag. Do not install by copying only `SKILL.md` when explicit-only invocation matters.

Existing affected installs may be repaired without changing the canonical module body:

- Codex: add the matching `agents/openai.yaml` beside the installed skill.
- Claude Code: use a local `user-invocable-only` override or reinstall the Claude-rendered artifact.

See [the installation guide](../installation.md) and [the Vietnamese installation guide](../vi/installation.md).
