# Dwi v0.2.5

Release status: approved for publication

Release type: parser-hardening and repository-integrity patch

Release date: 2026-07-26

## Summary

Dwi v0.2.5 closes two late review findings that arrived after `v0.2.4` publication and strengthens the repository beyond those individual cases.

The Codex metadata validator now accepts only a deliberately small, inspectable YAML subset. It fails closed on syntax that could hide, duplicate, redirect, or reinterpret the invocation policy, rather than attempting to approximate the full YAML language with permissive line matching.

This patch does not change canonical Dwi module bodies, module SHA-256 values, installed artifact shapes, native permissions, sandbox behavior, or the explicit-invocation contract.

## Fixed

- Rejected multiline double-quoted and single-quoted scalars before apparent policy lines can be misread as active mappings.
- Required YAML separation after mapping colons and before comment markers; values such as `false#note`, `interface:#note`, and `allow_implicit_invocation:false` are rejected.
- Rejected malformed plain scalars with reserved leading indicators, unsafe mapping separators, or control characters.
- Rejected literal and folded block scalars, flow collections, anchors, aliases, custom tags, YAML directives, document markers, sequences, explicit mapping keys, tabs anywhere in metadata, and UTF-8 BOM input.
- Kept one-line quoted interface values supported while requiring complete scalar closure and separated trailing comments on the same physical line.
- Changed unsupported YAML syntax from a best-effort skip to an explicit validation failure.

## Repository improvements

- Moved Codex metadata validation into one import-safe module used by production installation and regression checks.
- Added a dedicated adversarial policy-validation suite with 3 accepted and 30 targeted rejected fixtures.
- Built every adversarial fixture from canonical valid metadata, changed one target property, and asserted the specific rejection reason.
- Added the adversarial suite to `npm run check` and the public-release preflight path.
- Preserved `package.json.version = 0.2.0` as the machine-checked module-content baseline rather than conflating it with repository patch releases.
- Preserved the existing complete installed-artifact regression suite across all seven modules and both supported harness artifact shapes.

## Upgrade guidance

New installations should use `v0.2.5` after the immutable tag and GitHub Release are published.

Existing correct `v0.2.3` or `v0.2.4` installations do not need to be reinstalled solely because of this patch. The installed module content and explicit-only fields are unchanged. The patch hardens validation performed before future Codex artifacts are copied.
