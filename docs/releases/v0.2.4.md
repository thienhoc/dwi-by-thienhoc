# Dwi v0.2.4

Release status: draft, not approved for publication

Release type: validation-hardening patch

Release date: 2026-07-26

## Summary

Dwi v0.2.4 hardens two controls discovered in late review after the successful `v0.2.3` installation-contract release:

- Codex metadata validation now requires exactly one active `policy.allow_implicit_invocation` declaration whose YAML value is the boolean `false`.
- Release-record discovery now compares the triggering commit with its first parent, so a reviewed release merged through a merge commit is not silently skipped.

`v0.2.3` remains a valid immutable release. This patch does not change canonical Dwi module bodies or their SHA-256 values.

## Fixed

- Replaced substring matching for `allow_implicit_invocation: false` with an exact structural validator.
- Rejected lookalike keys such as `not_allow_implicit_invocation`.
- Rejected commented occurrences, `falsehood`, `true`, duplicate declarations, declarations outside the top-level `policy` block, incorrect indentation, and duplicate policy blocks.
- Made the installer import-safe so the validation suite can exercise the exact production parser without running the CLI entrypoint.
- Replaced commit-only release-record discovery with an explicit first-parent diff.
- Added regression assertions that require the workflow to stay pinned to `GITHUB_SHA` and to use first-parent release detection.

## Validation plan

Before publication, the release candidate must pass:

- Repository contract on Node.js 20 and 24.
- Installed-artifact contract for all seven modules across Codex and Claude Code.
- Adversarial Codex metadata fixtures covering lookalike, commented, falsehood, true, duplicate, wrong-block, wrong-indentation, and duplicate-policy cases.
- Workflow contract requiring `git diff --name-only "$first_parent" "$GITHUB_SHA"`.
- Existing overwrite, unknown-module, malformed-target, containment, symlink-alias, documentation, and cleanup tests.
- All actionable review threads associated with this hardening patch.
