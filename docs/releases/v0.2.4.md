# Dwi v0.2.4

Release status: approved for publication

Release type: validation-hardening patch

Release date: 2026-07-26

## Summary

Dwi v0.2.4 hardens controls discovered in late review after the successful `v0.2.3` installation-contract release:

- Codex metadata validation now verifies the effective YAML mapping rather than searching for a text fragment.
- The installer remains import-safe and now executes correctly when its entrypoint is reached through a symlink.
- Release-record discovery compares the triggering commit with its first parent, so a reviewed release merged through a merge commit is not silently skipped.

`v0.2.3` remains a valid immutable release. This patch does not change canonical Dwi module bodies, their SHA-256 values, or the installed artifact shapes.

## Fixed

- Replaced substring matching for `allow_implicit_invocation: false` with structural block-mapping validation.
- Required one unquoted top-level `policy` block and one unquoted direct child `allow_implicit_invocation` with YAML boolean value `false`.
- Rejected lookalike keys such as `not_allow_implicit_invocation`.
- Rejected comments posing as declarations, `falsehood`, `true`, duplicate declarations, quoted and escaped equivalent keys, nested declarations, wrong blocks, wrong indentation, flow mappings, and duplicate policy blocks.
- Canonicalized the direct-run comparison so the CLI executes through file or repository symlink paths while remaining safe to import in the regression suite.
- Replaced commit-only release-record discovery with an explicit first-parent diff.
- Added regression assertions requiring the workflow to stay pinned to `GITHUB_SHA` and to use first-parent release detection.

## Upgrade guidance

New installations should use the immutable `v0.2.4` release.

Existing correct `v0.2.3` installations do not need to be reinstalled solely because of this hardening patch. Canonical module content, checksums, installed files, and explicit-only fields are unchanged.

Projects that vendor or modify `agents/openai.yaml` should validate that `policy.allow_implicit_invocation` is one unquoted direct child of the single top-level `policy` block and has the YAML boolean value `false`.

See [the installation guide](../installation.md) and [the Vietnamese installation guide](../vi/installation.md).
